1.1 调研范围与结论速览

A · 记忆算法与评测

FSRS 生态、Duolingo HLR、Ebisu、Anki/SM-2、墨墨 SSP-MMC、含反应时的研究（SlimStampen/ACT-R、KAR3L）、公开数据集。

结论FSRS 作对照、HLR+反应时作实验组；anki-revlogs-10k 是唯一带毫秒级作答时长的大规模公开数据。

B · 词库、内容与发音

ECDICT、kajweb/dict、WordNet、wordfreq、CEFR、词根词缀、Tatoeba、Kokoro/Piper/edge-tts、DeepSeek/Qwen/Ollama、Instructor。

结论ECDICT（MIT，自带中高考标签）为主词典；发音用 Kokoro（Apache-2.0）离线预生成；LLM 用 DeepSeek + Instructor 预生成并人工抽审。

C · 工程栈与硬件

PWA/Flutter/Tauri/RN、PowerSync/ElectricSQL/CRDT、Anki/qwerty-learner、ESP32 墨水屏设备、FastAPI/PocketBase/Supabase、GrowthBook、DuckDB。

结论主推 PWA + SQLite-WASM + ts-fsrs + FastAPI；备选 Flutter + PowerSync；硬件走 ESP32-S3 + GxEPD2 + 7 键。

1.8 调研发现的关键风险

  • 评测数据与产品数据语义不一致：Anki 的 duration 是"看卡到按键"的总时长，含翻面阅读；词猎的 RT 是"呈现词到按三键"。公开数据上的增益不一定迁移，必须用自有数据复验。
  • 增益可能很小：benchmark 中 FSRS-7 与 LSTM 的 log loss 仅差约 0.003，RT 的边际增益需要较大样本才显著，内测前要做功效分析。
  • 三键自评有偏："绿"不等于真记得；需抽样插入拼写/选择题做客观校验。
  • 插队改变分布：阈值插队会改变复习时机，造成离线评估的选择偏差；上线后要保留随机化对照流量。
  • 墨水屏刷新延迟：局部刷新约 200–500 ms，全刷 1–2 s，会让刺激呈现时间失真；软件 Demo 的 RT 分布不能直接搬到硬件，需要在软件里模拟延迟或在硬件上重新标定。
  • 许可：Anki/AnkiDroid/KOReader/qwerty-learner 为 AGPL/GPL 只能参考；kajweb/dict 与有道音频无授权；XTTS 权重禁商用；edge-tts 走非官方接口；srs-benchmark 无 License；MaiMemo 与 anki-revlogs-10k 仅限研究。
  • 未成年人数据合规：需满足《个人信息保护法》《儿童个人信息网络保护规定》，监护人同意、最小化采集、境内存储；生成内容面向未成年人，需敏感词、事实性与超纲词三道检查，并关注生成式 AI 服务备案与标识义务（未核实适用范围）。
  • 离线时钟漂移：设备时钟不准导致日志乱序；用单调时钟 + 同步时校准偏移。

② Demo 架构方案ARCHITECTURE

2.1 Demo 的目标与边界

要验证什么
  • H1：加入反应时间等行为特征后，遗忘预测的 log loss / AUC 显著优于 FSRS-5 基线。
  • H2："P(遗忘)>阈值即插队"的调度，在同等学习时长下 7 日留存率高于固定间隔。
  • H3：三键 + 反应时的交互学生能接受（每次作答 ≤ 3 s，日均坚持 ≥ 15 min）。
明确不做
  • 不做硬件、不做蓝牙/固件，用网页/手机模拟三键。
  • 不做完整 3500 词内容精修，先覆盖中考核心 ~1600 词。
  • 不做家长端、商城、社交；只做学生端 + 实验后台。

2.2 总体架构

采用"离线优先客户端 + 轻后端"结构。调度与遗忘预测的推理放在客户端（保证断网可学、与未来硬件的纯离线模式一致），模型训练、LLM 内容生成和实验分析放在后端。

B. 遗忘模型：对照组与实验组

对照组 · FSRS-5

直接使用 ts-fsrs（客户端）与 py-fsrs / fsrs-optimizer（后端），默认参数起步，积累 ≥ 1000 条复习后每夜按用户拟合。可召回率 R(t)=（1 + t/(9·S))^-1，目标 R=0.9。

实验组 · RT-HLR（反应时增强）

以 Duolingo HLR 的半衰期回归为骨架 h = 2^(θ·x)，特征 x 增加：log 反应时、反应时 z 分数（相对该用户）、"绿但慢"计数、黄灯计数、错因类型、形近词混淆次数、时段（早/中/晚）。P(遗忘)=1-2^(-Δt/h)。

同时保留 HLR 原版（不含 RT）作为严格对照，使实验组与对照组只差反应时一个变量；SM-2 作为下限基线。第二阶段可改为"FSRS + 反应时修正项"：参考 SlimStampen 的 α 修正，用观测 RT 与期望 RT 的偏差调节 stability 增长系数，不脱离 FSRS 生态。

C. 本地调度器（Demo 的核心机制）

on_answer(word, rating, rt_ms):
  log_event(...)
  update_card(word, rating, rt_ms)              # 两个模型并行更新，按实验分组取其一决策
  if rating == RED:        push(five_min, word, +5min); push(tonight, word)
  elif rating == YELLOW:   push(thirty_min, word, +30min); push(tonight, word)
  elif rt_ms > slow_threshold(user):            # 绿但慢 → 濒临遗忘
                           push(tonight, word); mark(card, "fragile")
  else:                    schedule_by_model(word)  # 明天或更晚

next_item(now):
  due = [w for w in queues if w.due <= now]
  risk = [w for w in cards if P_forget(w, now) > τ and not w.seen_in(20min)]
  if due or risk:  return pick(due + risk, priority=core_word, P_forget)   # 插队，UI 显示"老朋友来看你"
  if new_budget_left(): return next_new_word()
  return next_scheduled_review()

阈值 τ 与慢反应阈值是实验参数（默认 τ=0.3，慢阈值取用户近 200 次绿灯反应时的 P75，冷启动 3 s），在实验后台可调。

D. 内容引擎

  • 静态层：ECDICT 释义 + 音标 + 词频 + 柯林斯星级 + zk/gk 标签；核心词按 gk/zk、Zipf 词频、collins、oxford、CEFR 加权分三档（核心/常用/拓展）；例句优先从 Tatoeba eng–cmn 检索；形近词表按编辑距离 ≤ 2 与 CMUdict 读音相近自动生成，LLM + 人工复核。
  • 生成层：LLM 根据提示模板生成"含近期错词的例句""对比卡片""周末错词故事"。生成在后端完成，经敏感词与年龄适配审核后写入 content_cache，客户端预拉取当日所需内容，保证离线可用。
  • 发音：Kokoro-82M 离线批量生成单词与例句音频（mp3），静态目录分发；音标用 CMUdict + ECDICT 补全；Demo 阶段不做真人音频。

4.5 风险与对策

风险影响对策
内测数据量不足以拟合个性化参数；RT 边际增益很小H1 结论不可靠先用 anki-revlogs-10k 做群体级验证并做功效分析；RT-HLR 采用群体参数 + 少量用户项；延长内测而非扩大功能
评测数据语义不一致（Anki duration 含阅读时间）公开数据增益不迁移公开数据只定方向，结论以自有三键 RT 日志复验为准；保留随机化对照流量避免插队带来的选择偏差
反应时噪声大（设备差异、分心）特征失效用户内 z 分数归一化；剔除 < 300 ms 与 > 15 s；记录设备类型
学生为了"快"而乱按绿灯数据污染、假记忆睡前战役用变形题型做校验；连续快绿后随机抽查中→英拼写
LLM 生成内容不当或难度不符合规与体验后端生成 + 审核 + 缓存，不在客户端实时调用；提示词限定词表难度；人工抽检
数据与代码许可商用受限Demo 用 ECDICT（MIT）、Tatoeba（CC BY）、Kokoro（Apache）等许可友好件；不碰 kajweb/dict、有道音频、XTTS；AGPL/GPL 项目只参考；研究数据集不进产品
未成年人数据合规法律风险监护人知情同意、最小化采集、境内存储；生成内容三道检查后入库，不在学生端实时调用 LLM
硬件过早投入资源浪费M2 前不启动硬件设计，只做竞品拆机与供应链访谈
