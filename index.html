先认识产品词猎是什么，想靠什么取胜，为什么先做软件

词猎是一台给初高中生背英语单词的小设备。屏幕上出一个词，学生在心里回忆它的意思，然后按三个键里的一个。

红键

不认识。

黄键

有点模糊。

绿键

认识。

设备还会顺手记下一件事：从词出现到按键，用了多久。这叫反应时。

设想中的设备用黑白墨水屏，也就是电子书阅读器那种屏。它不能触摸，不能上网闲逛，只有几个实体按键。让孩子离开手机背单词，是它的卖点之一。

背单词产品比的是什么

所有背词产品都要回答同一个问题：今天该复习哪些词。复习早了，词还记得很牢，白花时间。复习晚了，已经忘了，等于重学。

管这件事的那段程序叫调度算法，也就是替学生排复习日程的程序。一个背词产品聪不聪明，主要看它。

现成的答案叫 FSRS。它是一个公开、免费的调度算法，常见的背词软件已经内置了它，谁都能直接拿来用。所以词猎的算法要有价值，就得比它强。

词猎想靠什么取胜

构想稿里有四样别人没有的东西。前两样是核心，后两样是围绕它们的做法。

设想具体怎么做当初为什么觉得有用
用上反应时按了绿，但想了很久才按，就当成「会了但不牢」。只看对错发现不了这种词。看快慢能早一步发现。
自己的记忆模型给每个词估一个半衰期，也就是把握掉到一半要多少天。估的时候把反应时算进去。估得更准，复习就排得更准。
快忘了就插队估计某个词忘掉的可能超过三成，就不等排好的日子，马上插进来复习。抢在忘掉之前救回来。
绿但慢，睡前再练当天没答好的词，睡前换一种考法再过一遍。按红、按黄的算。按了绿但比自己平时慢的，也算。给不牢的词多一次巩固。

为什么先做软件

因为做硬件贵，而要验证的东西用手机就能试。

做一台设备要设计电路、开模具、备料。花钱多，周期长，做出来再改很难。

词猎赌的是排复习的办法。这套办法在手机上用三个大按钮就能跑起来，反应时也照样能记。

所以先做软件版，下文叫它 Demo。它证明办法有用，再投硬件。它证明办法没用，损失的只是几周时间。

要回答的四个问题软件版做出来，就是为了回答它们

软件版要回答四个问题，每个问题事先定好过关线。先定线再看结果，是为了不让自己事后找理由。

问题怎么量过关线
一、猜得更准吗让算法预测「这个词学生现在还记不记得」，再和学生的真实作答对照，算出预测误差。词猎的办法比 FSRS 误差低 5% 以上。比如 FSRS 是 0.40，词猎要到 0.38 以下。而且不能总是猜高，或者总是猜低。
二、记得更牢吗学完 7 天后，随机抽 50 个词考一次。两组花的学习时间要一样长。用词猎办法的那组，正确率高出 5 个百分点以上。比如对照组答对 70%，实验组要到 75% 以上。
三、学生用得下去吗看每天学多久，早中晚三次有没有做完，14 天后还在不在用。再用问卷问插队烦不烦。14 天后还在用的学生不少于六成。插队的打扰程度，五分制不超过 2 分。
四、家长愿意买吗访谈学生和家长：更想用手机还是单独的设备，愿意出多少钱。一半以上的家长，愿意为不用手机的设备付 299 元以上。

前两个问题问的是算法，后两个问的是产品。四个里只要第一、第二个不过关，「靠算法取胜」这个说法就站不住。

怎么比才公平

把试用的学生随机分成两组，学生自己不知道在哪一组。两组用同一个应用、同一批词，只有排复习的办法不同。这样两组的差别，就是办法的差别。

记住两个叫法，后面一直用。

对照组：只用 FSRS。它代表「现成的免费方案」。

实验组：用词猎自己的办法。它代表「词猎的设想」。

正式比的就是这两组。另外还留两个小参照，用来分清功劳该算在谁头上。一个是不加反应时的同款算法。一个是实验组里一小部分不插队的学生。后面讲到时再细说。

后来的进展：前两个问题已经用假学生测过，都没过关。后两个问题还没有答案，要等真人。见后来怎样了。

调研：哪些东西不用自己做四份成果之一 · 开源项目调研

结论：要用的零件大多有现成的、免费的。真正要自己做的只有一样，把反应时用进算法。

这里说的现成零件，指开源项目，也就是别人把做好的程序或数据公开出来，允许大家拿去用。每个项目都带一份许可，写明能不能拿去做商品卖钱。所以每样东西除了看好不好用，还要看许可。

调研查了三类：排复习的算法，词库和发音这类内容，做应用和做设备的工具。下表只列最后选中的。

三个最要紧的发现

有人做过几乎一样的事

一个大学研究组做过一套背词系统。它根据学生答题的快慢，随时修正每个词忘得有多快。他们还发现，这个数能预测考试成绩。

这和词猎的核心想法几乎一样，说明方向有依据。但它的应用没有公开，只能借鉴思路。

好处可能很小

在公开的评测里，用上作答用时的模型只比 FSRS 准一点点。预测误差越低越准。用上用时的模型是 0.3332，FSRS 是 0.3363。

差距这么小，要很多数据才看得出来。所以找学生之前，要先算清楚需要多少人、学多久。

有几样流行的东西不能碰

几个很火的背词开源项目，许可不允许拿去做商品，只能看，不能抄代码。

有一份流传很广的中高考词库，数据是从别家应用里扒下来的，没有授权。这些都不进产品。

调研时就看到的风险

  • 公开数据里的「用时」和我们的不是一回事。那份数据记的是从看到卡片到按键的总时间，中间包括翻看答案。词猎记的是从词出现到按三键。在公开数据上有效，不代表在词猎上有效，必须用自己的数据再验一遍。
  • 按绿不等于真记得。三个键是学生自己评的。要时不时插一道拼写题或选择题，客观地查一下。
  • 插队会干扰评估。插队改变了每个词被复习的时机，事后分析容易看走眼。所以要一直留一部分学生不插队，当参照。
  • 墨水屏刷新慢。换一小块要 0.2 到 0.5 秒，整屏重刷要 1 到 2 秒。这会让反应时变样。软件版量出来的快慢标准，到硬件上要重新量。
  • 未成年人的数据要守规矩。要监护人同意，只收必要的数据，数据存在境内。AI 写的内容给孩子看之前，要过敏感词、事实、超纲词三道检查。
  • 设备时钟不准。断网时设备的时间会跑偏，记录的先后可能乱。办法是用一个只增不减的计时器，联网时再对表。

软件版怎么搭四份成果之二 · 架构方案

结论：软件版分两半。手机上的一半负责出词和排复习，断网也能用。服务器上的一半负责把算法调准、准备内容、统计结果。

做什么，不做什么

做

  • 学生用的学习应用。
  • 给研究人员看数据的后台。
  • 先覆盖中考最核心的约 1600 个词。

不做

  • 不做硬件。用手机或网页上的三个按钮代替实体键。
  • 不做全部 3500 个词的精修。
  • 不做家长端、商城和社交功能。

两半各管什么

在哪管什么
手机上出词，收按键，记反应时。
排复习：答完一个词，立刻决定它下次什么时候出现。
把每次作答存在手机里，有网时再传回去。
服务器上收所有学生的作答记录。
每天夜里用新记录把算法的参数调准，再发回手机。
提前让 AI 写好例句和故事，审核后发到手机。
统计两组学生谁学得好。

参数，也就是算法里的几个旋钮。它们决定算法认为这个学生忘得快还是慢。每晚调参数，就是照着新记录把旋钮重新拧一遍。

为什么排复习放在手机里。将来的设备平时不联网，排复习必须在本机完成。软件版照这个条件来做，以后搬到硬件上就不用重来。

每答一个词，记下什么

每答一次，记一行流水账。只往后加，不回头改。这样记录不会被后来的操作弄乱，事后可以原样重放一遍。

  • 哪个学生，哪台设备，哪个词。
  • 什么时候答的。
  • 按了红、黄、绿哪个键，用了多少毫秒。
  • 这道题是哪种考法。比如看英文想中文，或者听读音选意思。
  • 这道题为什么会出现。比如是新词，是到日子的复习，还是插队。
  • 答错的话，错因是什么，和哪个词搞混了。
  • 出这道题时，算法估计学生有几成把握记得。

最后一项是为了事后检查算法估得准不准。

两组各用什么算法

对照组：FSRS

直接用现成的。一开始用通用的参数。一个学生攒够 1000 条复习记录后，每晚按他自己的数据调一次。

它等学生对一个词的把握掉到九成时，安排复习。

实验组：我们的模型

底子是多邻国的 HLR。它给每个词估一个半衰期，也就是把握掉到一半要多少天。

我们往里加了这些输入：这次按键用了多久。比这个学生平时快还是慢。按过几次「绿但慢」。按过几次黄。错因是哪一种。和长得像的词混过几次。是早上、中午还是晚上学的。

还会留一个不加反应时的 HLR 当参照，也就是前面说的第一个小参照。它和我们的模型只差反应时这一样，差出来的效果才能算在反应时头上。

排复习的规矩

一句话：答得越差，回来得越快。估计快忘了，就插队。

学生怎么答这个词接下来怎么办
红，不认识5 分钟后再出一次。当晚睡前再练。
黄，模糊30 分钟后再出一次。当晚睡前再练。
绿，但按得慢当晚睡前再练，并标成「不牢」。
绿，按得快交给算法排，明天或更晚再出。

什么叫慢。拿学生自己最近 200 次按绿的用时来比。比其中四分之三都慢，就算慢。刚开始没有记录时，先按 3 秒算。

什么时候插队。不管一个词排在哪天，只要算法估计它忘掉的可能超过三成，而且最近 20 分钟没出现过，它就插到前面来。几个词同时要插，核心词优先。

出题的先后。先出到点该回来的词和插队的词。没有了，再学新词，新词每天有上限。再没有，做算法排好的常规复习。

后来的进展：在假学生实验里，插队和睡前再练都没多记住词，睡前再练还让学生更容易放弃。现在的建议是插队默认关，睡前再练去掉。

两组的公式

对照组 FSRS-5：ts-fsrs 在客户端，py-fsrs 与 fsrs-optimizer 在后端。可召回率 R(t)=(1 + t/(9·S))^-1，目标 R=0.9。

实验组 RT-HLR：半衰期回归 h = 2^(θ·x)，P(遗忘)=1-2^(-Δt/h)。特征 x 增加 log 反应时、相对该用户的反应时 z 分数、绿但慢计数、黄灯计数、错因类型、形近词混淆次数、时段。另留 HLR 原版作严格对照，SM-2 作下限基线。第二阶段可改为 FSRS 加反应时修正项：参考 SlimStampen 的 α 修正，用观测 RT 与期望 RT 的偏差调节 stability 增长系数。

本地调度器的逻辑

on_answer(word, rating, rt_ms):
  log_event(...)
  update_card(word, rating, rt_ms)              # 两个模型并行更新，按实验分组取其一决策
  if rating == RED:        push(five_min, word, +5min); push(tonight, word)
  elif rating == YELLOW:   push(thirty_min, word, +30min); push(tonight, word)
  elif rt_ms > slow_threshold(user):            # 绿但慢 → 濒临遗忘
                           push(tonight, word); mark(card, "fragile")
  else:                    schedule_by_model(word)  # 明天或更晚

next_item(now):
  due = [w for w in queues if w.due <= now]
  risk = [w for w in cards if P_forget(w, now) > τ and not w.seen_in(20min)]
  if due or risk:  return pick(due + risk, priority=core_word, P_forget)   # 插队，UI 显示"老朋友来看你"
  if new_budget_left(): return next_new_word()
  return next_scheduled_review()

阈值 τ 与慢反应阈值是实验参数，在实验后台可调。默认 τ=0.3，慢阈值取用户近 200 次绿灯反应时的 P75，冷启动 3 s。

事项规矩
反应时怎么计词在屏幕上画完的那一刻开始计，第一次按键时停。最长计 15 秒，超过就按黄处理，并记一笔超时。
按键电脑上：左键是红，下键是黄，右键是绿，上键听发音。手机上：底部三个大圆按钮，既有颜色也有字，色弱的学生也能分清。
防误触换词后的 0.25 秒内，按键不算。连续按同一个键 5 次，提示「认真答哦」，并记一笔。
插队提示屏幕顶上那行字换成「有个老朋友来看你」，手机短震一下。不弹窗，不打断节奏。
断网所有学习都在本机完成。有网时在后台悄悄上传，失败了自己重试。界面上不显示有没有网。
进度怎么显示用一段简笔动画表示「遗忘曲线被拉平了」。不显示分数。
每天的节奏早上、30 分钟后、睡前，一天三次。软件版没有「开机」这个动作，用手机通知或微信提醒来代替。

每一段交出什么，怎么算过关

阶段第几周交出什么怎么算过关
准备词库和数据1 到 2清洗好的词库，至少 1600 个中考核心词，带释义、音标、例句、词频。形近词表。全部读音。读取公开数据的程序。抽查词条，98% 以上正确。在公开数据上，能算出和别人公布的一样的 FSRS 成绩。
做算法2 到 4接好 FSRS。做出我们的模型，外加两个当参照的算法。给各种算法打分的程序。在公开数据上给出三种算法的对比表。算清楚找学生试用需要多少人。
做手机端2 到 5界面一到六，三键和反应时，本机存储，排复习，断网后补传。断网连续学 30 分钟不丢记录。反应时的误差小于 20 毫秒，用自动按键的程序来验。
做服务器和内容4 到 6收记录的程序，每晚调参数的程序，AI 写的例句和故事连同审核，读音文件，实验后台。人工抽查 50 条例句，难度和内容都合格。能给每个学生发回他自己的参数。
找学生试用6 到 930 到 60 名学生，随机分成对照组和实验组，每天学三次。每人至少有 15 天的有效记录。每天出故障的比例低于 1%。
分析和决定9 到 10四个问题的结果报告，访谈记录，要不要做硬件的建议。给出明确的一句话：继续、调整，还是停止。

可能出什么岔子，怎么防

担心什么会怎样怎么防
试用的学生太少，或者反应时带来的好处太小第一个问题得不出可靠的结论先在那份公开数据上验一遍，算清楚需要多少人。宁可延长试用，也不加功能。
公开数据里的用时和我们的不是一回事公开数据上有效，到词猎上未必公开数据只用来定方向。结论以学生的真实记录为准。一直留一部分学生不插队，当参照。
反应时很乱，设备不同、学生走神都会影响这个信号用不上只和学生自己比快慢，不和别人比。短于 0.3 秒和长于 15 秒的不算。记下设备类型。
学生为了快，乱按绿记录不可信，以为记住了其实没有睡前换一种考法再考。连续很快按绿之后，随机抽一道拼写题。
AI 写的内容不合适，或者太难合规出问题，体验差内容在服务器上提前生成、审核、存好，不在学生面前现写。限定用词范围。人工抽查。
数据和代码的许可以后不能商用只用许可允许商用的词典、例句和发音。来路不明的词库和音频不碰。只供研究的数据不进产品。
未成年人的数据法律风险监护人知情同意，只收必要的数据，存在境内。AI 内容过三道检查再入库。
硬件投入太早白花钱出结论之前不启动硬件设计，只做竞品拆机和供应商访谈。

做法上的三处不同

计划里实际上
十周，三到四个人。两天做完。计划是按人来写程序估的。实际让 AI 同时写四个部分，人只管定规矩和验收。做出来的版本功能齐全，但还没经过真人长期使用。
先用公开数据给算法打分，再找 30 到 60 名学生试 3 周。先造了 30 个假学生，让他们用真的软件学 90 天。那份公开数据这次没用上，真人也还没找。
对照组和实验组比一次。比了六轮。前三轮找原因，后三轮试改法。

假学生，也就是一段模仿学生的程序。它有自己的记忆，会忘词，会偷懒，也会放弃。用它测一轮只要几分钟，还能直接看到它到底记住了没有。它替代不了真人，但能先筛掉明显不行的想法。

四个问题现在的答案

问题现在的答案
一、猜得更准吗没证实 在公平的考法下，我们的模型估得不如 FSRS 准。什么叫公平的考法，见表下的说明。
二、记得更牢吗没证实 第一次比，实验组多记了约一成的词。但它每天也多做了三成多的题，这不算公平。按计划的规矩把题量拉平再比，我们的模型反而少记两到三成。
三、学生用得下去吗待真人 假学生只给了一个提醒：睡前再练会让人更容易放弃。
四、家长愿意买吗待真人 还没有做访谈。

什么叫公平的考法。假学生怎么忘词，是写进程序里的一套规则。如果这套规则恰好和我们的模型是同一个路子，我们的模型自然猜得准，这不算数。所以又换了一套和我们的模型无关的规则来考。这样考下来，它估得不如 FSRS 准。

计划里的设计现在的建议
实验组用我们的模型排复习改用 FSRS，并把复习排得勤一些。计划里是把握掉到九成才复习。现在暂定掉到九成三就复习，掉得少一点就练，所以更勤。
快忘了就插队默认关掉。
绿但慢，睡前再练去掉。
让反应时影响排复习反应时照常记录，先不让它影响排复习。等真人数据回来再看。

没有变的。调研选出的词典、例句、发音这些零件都用上了。三键作答、断网可用、每答一次记一行流水账，也都照这页做了。设备形态和界面好不好，要等真人来试。
